# LOOP — каталог музыкальных альбомов

Каталог альбомов с поиском, фильтрами, личным списком со статусами, оценками и заметками, рецензиями и админ-режимом.
Вариант: собственная тема (по образцу группы В, каталог фильмов/сериалов).

**Адрес сайта:** ВСТАВЬТЕ_АДРЕС (https://...)
**Тестовая учётная запись:** почта ВСТАВЬТЕ, пароль ВСТАВЬТЕ

## Как запустить локально
Нужен Python 3.10+. Из корня проекта:

```
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn backend.main:app --reload
```

Откройте http://127.0.0.1:8000. База `loop.db` создаётся и заполняется 21 альбомом при первом запуске.
Описание API генерируется автоматически: http://127.0.0.1:8000/docs.
Треклисты подтягиваются из Apple iTunes Search API, для них нужен интернет.

## Как запустить через Docker
Нужен Docker с Docker Compose.

```
cp .env.example .env            # заполните значения в .env
docker compose up -d --build
```

Для проверки на своей машине без домена: в `.env` укажите `DOMAIN=localhost` и откройте https://localhost
(браузер предупредит о самоподписанном сертификате). На сервере с доменом Caddy сам получает бесплатный сертификат Let's Encrypt.
База хранится в томе `loop-data`, поэтому не пропадает при перезапуске контейнера.

## Настройки (переменные окружения)
| переменная | назначение |
|---|---|
| LOOP_DB_PATH | путь к файлу базы (в контейнере `/data/loop.db`) |
| LOOP_COOKIE_SECURE | `1` — cookie входа передаётся только по HTTPS (в compose включено) |
| LOOP_ADMIN_EMAIL, LOOP_ADMIN_PASSWORD | администратор; создаётся при запуске, если заданы обе |
| LOOP_DEMO_EMAIL, LOOP_DEMO_PASSWORD | тестовая учётная запись; создаётся при запуске, если заданы обе |
| DOMAIN | адрес сайта для Caddy (только в `.env` для compose) |

## Структура
- `frontend/` — страницы, `style.css`, `script.js`, папка `img/`
- `backend/main.py` — обработчики API, `auth.py` — пароли и сессии, `config.py` — настройки, `db.py` — схема и наполнение базы
- `backend/albums_seed.json` — начальные данные каталога (21 альбом)
- `Dockerfile`, `docker-compose.yml`, `Caddyfile` — развёртывание

## База данных (SQLite)
**users** — пользователи: `id` (INTEGER, PK), `name` (TEXT), `email` (TEXT, UNIQUE), `password_hash` (TEXT, хеш argon2), `created_at` (TEXT).

**albums** — каталог: `id` (PK), `title`, `artist` (TEXT), `year` (INTEGER), `genre` (крупный жанр для фильтра), `style` (точный жанр),
`label` (может быть пустым), `rating` (REAL, стартовая оценка), `cover`, `description` (TEXT), `mb_title` (название для поиска треклиста, может быть пустым).

**library** — личный список пользователя (связь «многие ко многим» между users и albums): `user_id` (FK → users.id), `album_id` (FK → albums.id),
`status` (want / listening / listened, может быть пустым), `rating` (INTEGER 1–5, может быть пустым), `note` (TEXT), `favorite` (INTEGER 0/1), `added_at` (TEXT).
Первичный ключ — пара (user_id, album_id).

**reviews** — рецензии: `user_id` (FK), `album_id` (FK), `text`, `updated_at`; ключ — пара (user_id, album_id), одна рецензия на альбом.

**messages** — сообщения из формы контактов: `id`, `name`, `email`, `text`, `created_at`.

**sessions** — вход пользователя: `token_hash` (PK), `user_id` (FK → users.id), `expires_at`.

**album_view** — представление: альбом с итоговой оценкой (среднее по оценкам слушателей, пока их нет — стартовая), числом оценок и рецензий.

## API
| метод и путь | доступ | что делает |
|---|---|---|
| GET /api/health | всем | проверка, что сервер и база работают |
| GET /api/albums, GET /api/albums/{id} | всем | список и один альбом |
| GET /api/albums/{id}/ratings | всем | сводка и распределение оценок |
| GET /api/albums/{id}/reviews | всем | рецензии альбома |
| GET /api/genres | всем | жанры с числом альбомов, поиск по названию |
| POST /api/contact | всем | сообщение из формы контактов |
| POST /api/auth/register | всем | регистрация, сразу выполняет вход |
| POST /api/auth/login, POST /api/auth/logout | всем | вход и выход |
| GET /api/me, PUT /api/me, POST /api/me/password | вошедшим | профиль, смена имени и пароля |
| GET /api/library | вошедшим | мой список |
| PUT /api/library/{album_id} | вошедшим | статус, оценка, заметка, «любимое» |
| PUT, DELETE /api/albums/{id}/review | вошедшим | своя рецензия |
| GET /api/stats | вошедшим | статистика кабинета |
| POST /api/albums, PUT, DELETE /api/albums/{id} | администратору | управление каталогом |
| GET /api/messages, DELETE /api/messages/{id} | администратору | сообщения из формы контактов |

## Безопасность
- Пароль хранится только как хеш argon2 (библиотека `argon2-cffi`).
- Все SQL-запросы параметризованные: значения передаются отдельно от текста запроса.
- Права проверяются на сервере: без входа методы личного списка отвечают 401, методы администратора отвечают 403 обычному пользователю, а каждый запрос работает только с данными своего пользователя.
- Сессия — случайный токен в HttpOnly-cookie; в базе хранится только его хеш. На хостинге cookie помечается Secure.
- Секреты и пароли администратора и тестового пользователя берутся из переменных окружения, в репозитории их нет.

## Что сделано
**ПР 1:** страницы, общий `style.css`, Grid и Flexbox, семантическая разметка, `alt` у всех изображений.
**ПР 2:** поиск, фильтры, сортировка, форма контактов с проверкой, треклисты из Apple iTunes через `fetch` с индикатором загрузки и обработкой ошибок.
**ПР 3:** сервер на FastAPI, база SQLite, регистрация и вход, личный список со статусами, оценки, заметки и рецензии, кабинет со статистикой, админ-режим. Страницы получают данные с сервера.
**ПР 4:** зависимости зафиксированы, настройки вынесены в переменные окружения, Dockerfile и docker-compose, HTTPS через Caddy.
